## Open issues

### Top tier — self-fetch from a moving ref

- `tests/e2e/scripts/setup_rootless.sh:4-10` — `github_url="https://raw.githubusercontent.com/k3s-io/k3s/main/k3s-rootless.service"` followed by `curl -LJO "$github_url"`. The script then drops the file under `/home/vagrant/.config/systemd/user/` and runs it. Anyone with push access to `k3s-io/k3s@main` controls the bytes; the fetch happens at vagrant-provision time, after the test repo has already been checked out at a specific SHA — so the sibling file in the working tree (`k3s-rootless.service` at the repo root) would be the safer source. Replace with `cp ../../../k3s-rootless.service "$destination_path/"` (relative-path copy) or pin the URL to `${VERSION_K8S}` / a SHA. _(see wiki §4.2)_

### High — production build pulls source by tag, not by SHA

- `scripts/build:168` — `git clone --single-branch --depth=1 --branch=$VERSION_CNIPLUGINS https://github.com/rancher/plugins.git $WORKDIR`. `VERSION_CNIPLUGINS="v1.9.1-k3s1"` (`scripts/version.sh:58`). The cloned tree compiles into the `cni` binary that ships in every k3s release. A retag of the upstream tag swaps the bytes; depth=1 prevents a later upgrade to a SHA without re-cloning.
- `scripts/build:171` — `git clone --single-branch --depth=1 --branch=$VERSION_FLANNEL_PLUGIN https://github.com/flannel-io/cni-plugin.git plugins/meta/flannel`. `VERSION_FLANNEL_PLUGIN="v1.9.0-flannel1"` (`scripts/version.sh:59`). Same threat as above; the clone feeds the embedded flannel CNI plugin.
- `scripts/download:27` — `git clone --single-branch --branch=${VERSION_RUNC} --depth=1 https://github.com/opencontainers/runc ${RUNC_DIR}`. `VERSION_RUNC` derives from `go.mod` via `get-module-version`; the runc source feeds the build.
- `scripts/download:35` — `git clone --single-branch --branch=${VERSION_HCSSHIM} --depth=1 https://github.com/microsoft/hcsshim ${HCSSHIM_DIR}` (Windows path). Same shape.
- `scripts/download:43` — `git clone --single-branch --branch=${VERSION_CONTAINERD} --depth=1 https://${PKG_CONTAINERD_K3S/\/v*/} ${CONTAINERD_DIR}`. Pulls containerd's source for the embedded build. Same shape.
- `scripts/download:47` — `curl -sfL ${CHARTS_URL}/${CHART_NAME}/${CHART_FILE} -o ${CHARTS_DIR}/${CHART_FILE}` (`CHARTS_URL=https://k3s.io/k3s-charts/assets`). ### Advisory

- **Renovate / Dependabot coverage gap.** `.github/dependabot.yml` configures `github-actions` and `docker` (across 6 directories), but not `gomod`. Go module updates land manually today; add a `gomod` ecosystem block (matched against `/`) so transitive vulnerabilities surface as PRs, or document why manual updates are preferred (k3s pins to a specific Kubernetes release line; full automation would fight that).
- **Embedded chart digests.** Even if `scripts/download:47` adopted SHA verification (above), `Chart.yaml`/`Chart.lock` does not exist for the in-repo chart bundles — the chart tarballs come pre-rendered. Mention this is by design when filing the chart-SHA issue, so the fix lands as a `*_SHA256` constant per chart rather than `helm dependency update`.
- **`package/rpm/repo-setup.sh:1-8`** — emits `/etc/yum.repos.d/rancher.repo` with `gpgcheck=1` and `gpgkey=https://rpm.rancher.io/public.key`. The signing posture is correct, but the key is fetched on first install over HTTPS without a stored fingerprint; a compromised `rpm.rancher.io` could swap both key and packages on the same install run. Vendor the public key into the repo and reference it via a `file://` path (or via an installed `rancher-keyring` package), then drop `repo_gpgcheck=0` (already not set, so this is just hardening).
- **`Dockerfile.local:18`** — `RUN GOPROXY=direct go install golang.org/x/tools/cmd/goimports@gopls/v0.20.0`. `GOPROXY=direct` bypasses the module proxy, so the `go.sum` populated for the workspace `go.mod` does NOT cover this fetch. Either drop `GOPROXY=direct` (the proxy is the trust anchor) or populate a sidecar `go.sum` for the tool install.
- **`scripts/version.sh:88-89`** — `VERSION_GOLANG="go"$(curl -sL "${GO_VERSION_URL}" | tr -d '[:space:]')`, fetching `https://raw.githubusercontent.com/kubernetes/kubernetes/${VERSION_K8S}/.go-version`. URL is tag-pinned to a third-party tag; output becomes the build's Go version. Low risk (k8s tag retag would also break wider builds), but worth noting that the bytes are unverified.

## Retro: dependency types not explicitly covered

- **R1. `curl` whose stdout drives `$(...)` substitution.** `scripts/version.sh:88-89` runs `VERSION_GOLANG="go"$(curl -sL "${GO_VERSION_URL}" | tr -d '[:space:]')`. The captured string becomes the build's Go version. **Where missed:** the inline-download filter requires `-o`/`-O`/pipe-to-shell/`>` redirect/archive extension; a `curl … | tr` capture matches none. **Proposed change:** add a sub-rule to the inline-download detector: `curl`/`wget` whose call appears inside `$(...)` or backtick substitution AND whose URL host sits outside the repo's own remotes is an unverified fetch. Severity is "advisory" because the captured string is rarely executed, but the version that drives the toolchain merits a flag.

- **R2. `GOPROXY=direct` cancels go.sum verification.** `Dockerfile.local:18` sets `GOPROXY=direct go install ...`. The script bucketed it as a `go install` covered by the Go module proxy, but `direct` bypasses the proxy. **Where missed:** the Run-from-network rule treats every `go install` as proxy-verified. **Proposed change:** when classifying `go install`, scan the same shell statement (and the surrounding `ENV`/`ARG` lines for Dockerfiles) for `GOPROXY=direct`, `GOPROXY=off`, or any `GOPROXY` whose final fallback is `direct`. Downgrade to "open issue" unless a sibling `go.sum` covers the install target.

- **R3. `runtime_repo_file` advisory with empty `disabled[]` is noise.** `package/rpm/repo-setup.sh:1` surfaced as a runtime repo emission, but the file enables `gpgcheck=1` with no bypass keys. The "disabled: —" rendering reads as a finding. **Where missed:** the `package_manager_signature_bypass[]` detector emits every `cat > /etc/yum.repos.d/...` it sees, regardless of bypass content. **Proposed change:** suppress `runtime_repo_file` entries whose `disabled[]` is empty AND whose `gpgkey=` line points to a `file://` path or a constant in-repo key. Surface only when bypass keys appear, when the key is fetched over the network without a stored fingerprint, or when no `gpgkey` is set at all.

- **R4. Wrapper-style chart bundles bypass the Helm dependency check.** `scripts/download:43-48` downloads chart tarballs into `build/static/charts/` without a `Chart.yaml`/`Chart.lock` anywhere in the repo. **Where missed:** the Helm-dependency rule looks for `Chart.yaml`/`Chart.lock` siblings; a script-driven bundle skips both. **Proposed change:** when an inline-download writes into a directory whose name matches `*charts*` AND the URL ends in `.tgz`, treat it as an embedded-chart fetch and require either a per-chart `*_SHA256` constant in scope or a sibling `Chart.lock`.

- **R5. `argref_froms` defaults deserve sub-classification.** `Dockerfile.local`/`Dockerfile.manifest`/`Dockerfile.test` all read `ARG GOLANG=golang:1.26.2-alpine3.22` then `FROM ${GOLANG}`. The script files them as advisory `argref_froms`, hiding that the in-repo defaults pin by tag (not digest). When CI overrides with a digest, the default is moot; otherwise the default applies. **Proposed change:** when an `argref_from` resolves to a default value declared in the same file, classify the default by the same pinned/unpinned rule as a literal `FROM`. Flag tag-only defaults as "open issue (default applies when caller does not override)" rather than burying them under advisory.
